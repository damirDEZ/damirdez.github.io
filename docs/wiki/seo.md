# Карточка ссылки, иконки и meta-теги

Сверено с кодом: 2026-11-25 (T-008, коммита ещё нет).

Когда ссылку на сайт отправляют в Telegram или другой мессенджер, под ней видна карточка: заголовок, описание и картинка 1200×630. На вкладке браузера и на экране телефона — иконка «D.». Всё по одобренному макету `docs/design/og/og.html` (Дамир 25.11; описание — `og.md`, снимок — `og-1360.png`).

## Что в `<head>` каждой страницы

Пишет `src/layouts/Base.astro`; страница передаёт свои `title`, `description`, `image` и `type` через props (`image` обязателен — без него `npm run check` упадёт на проверке типов).

| Тег | Откуда |
|---|---|
| `<title>`, `description` | props страницы; у главной — значения по умолчанию в `Base.astro`, у кейса — «<title> — Case study · Damir» и лид (`docs/wiki/case.md`) |
| `link rel="canonical"`, `og:url` | полный адрес страницы: начало из `site` (`SITE_URL`) + путь с подпапкой (`base`) |
| `og:title`, `og:description` | те же `title` и `description` |
| `og:image` | полный адрес карточки: `site` + `withBase(image)`; главная — `og/home.png`, кейс — `og/<slug>.png` (`ogImagePath()` из `src/lib/og.ts`) |
| `og:image:width`, `og:image:height` | 1200 и 630 (`ogImageSize` в `src/lib/og.ts`) |
| `og:type` | `website` — главная, `article` — кейс |
| `og:site_name` | `linkCard.siteName` в `src/data/link-card.ts` («Damir») |
| `twitter:card` | `summary_large_image` — крупная картинка (X/Twitter и те, кто читает этот тег) |
| `theme-color` | `#0a0a0c` — фон сайта (`--bg`); цвет панели браузера на телефоне |
| `link rel="icon"` 16, 32, 48 · `apple-touch-icon` 180 | файлы из `siteIcons` в `src/lib/og.ts`, пути через `withBase()` |

Адреса:
- На GitHub Pages `SITE_URL` (`https://<ник>.github.io`, без подпапки) и `BASE_PATH` (подпапка) задаёт workflow (`docs/wiki/site.md` → «Переменные»); адрес = `SITE_URL` + `BASE_PATH` + путь. Пример с `BASE_PATH=repo`: `og:image` = `https://<ник>.github.io/repo/og/home.png`, иконка — `/repo/favicon-32.png`.
- Локально `SITE_URL` не задан — Astro подставляет `http://localhost:4321`. Карточку по такой ссылке мессенджер не покажет, это нормально: нужна выложенная версия.
- `favicon.ico` (16, 32, 48 внутри) лежит в корне сайта для программ, которые спрашивают `/favicon.ico` сами, не читая `<head>`; в `<head>` не подключён — браузеру хватает PNG. В подпапке (`<ник>.github.io/<репо>/`) корень домена не наш — там `/favicon.ico` отдаёт главный сайт ника, браузер берёт иконку из `<head>`.

## Карточки ссылки (`npm run og`)

`scripts/og.mjs` рисует PNG 1200×630 в `public/og/` в установленном Google Chrome (`playwright-core`, как `npm run shots`; другой Chrome — `CHROME_PATH`). Готовые PNG лежат в репозитории: сборка и GitHub Actions их не рисуют, только копируют.

| Файл | Что на карточке | Откуда |
|---|---|---|
| `public/og/home.png` | логотип «DAMIR.», «Telegram @Dasifor», фраза «Videos, websites and games — *made fast, with AI.*», роли, три кадра с подписями | фраза, подпись «Telegram» — `src/data/link-card.ts`; ник — `contacts.ts`; роли — `hero.ts` (`eyebrow`); кадры — первые три работы `selected-work.ts`: картинка (или градиент) и подпись `cardLabel` самой работы (нет — начало `kind` до « · »), так что при перестановке работ подпись едет вместе с картинкой; работ меньше трёх — кадры делят ширину |
| `public/og/<slug>.png` — на каждый кейс | логотип, Telegram, название работы, тип работы, обложка | `cases.ts`: `title`, `eyebrow`, `cover.media` (картинка или градиент; у сайта видна верхняя часть, у ролика — середина) |

Шаблон — в `scripts/og.mjs` (стили из макета). Цвета — токены `src/styles/tokens.css`, градиенты-заглушки — из `src/components/home/Frame.astro` (не копией), шрифты — те же `@fontsource`, что на сайте, вшиты в шаблон. Картинки работ из `public/` тоже вшиваются; `https://…` — грузятся по адресу, и в отпечаток попадает только адрес: новая картинка по тому же адресу «устаревшей» карточку не сделает — тогда `npm run og -- --force`.

Отличия от макета:
- без скругления углов (в макете 4px — для витрины; мессенджер скругляет сам);
- средний кадр — градиент работы «AI film» из Selected work (`g4`, красный), в макете — `g1` (фиолетово-оранжевый): кадры берутся из работ, чтобы настоящие картинки попали в карточку сами;
- карточка кейса в макете не нарисована: тот же шаблон, вместо фразы — название, вместо ролей — тип работы (`eyebrow`), вместо трёх кадров — обложка во всю ширину (высота — сколько остаётся, от 150px).

При рисовании `npm run og` падает, если заголовок не помещается в две строки, подпись — в одну, кадр ниже 150px или наезжает на текст, не загрузился шрифт или картинка. Тогда — сократить текст в данных.

### Когда перерисовывать

`npm run og` — после правки:
- фразы, подписей или ника: `link-card.ts`, `contacts.ts` (Telegram), `hero.ts` (`eyebrow`);
- первых трёх работ Selected work (картинки, градиенты, `cardLabel` / `kind`, порядок) — `selected-work.ts`;
- кейсов: новый, удалённый, переименованный `slug`, другое название, `eyebrow` или обложка — `cases.ts`; замена файла картинки в `public/`;
- шаблона в `scripts/og.mjs`, токенов `--bg`, `--text`, `--text-2`, `--accent`, градиентов в `Frame.astro`, версии шрифтов.

Смена адреса сайта (`SITE_URL`, `BASE_PATH`, свой домен) карточек не касается — адреса на картинке нет, а теги в `<head>` пересоберутся сами.

Забыл — `npm run check` (и CI перед выкладкой) упадёт: «public/og/…: устарела — …. Перерисуй: npm run og».

- `npm run og` — рисует только недостающие и устаревшие карточки, удаляет карточки кейсов, которых больше нет.
- `npm run og -- --force` — перерисовать все (например, после обновления Chrome).
- `npm run og -- --check` — только проверить.

После — посмотри картинки в `public/og/` глазами.

## Иконки (`npm run icons`)

`scripts/icons.mjs` рисует по макету «D» (Space Grotesk 700, `--text`) и оранжевую точку (`--accent`) на `--bg`:

| Файл | Размер | Вид |
|---|---|---|
| `public/favicon-16.png` | 16 | скругление 4, без рамки, прозрачные углы |
| `public/favicon-32.png` | 32 | скругление 7, без рамки, прозрачные углы |
| `public/favicon-48.png` | 48 | скругление 10, без рамки (в макете нет — между 32 и 64) |
| `public/apple-touch-icon.png` | 180 | скругление 40, рамка 1px `#2a2a33`; без прозрачности — углы залиты `--bg` (iOS скругляет сам, прозрачное залил бы чёрным) |
| `public/favicon.ico` | 16, 32, 48 | те же PNG внутри одного файла |

Список файлов и размеров — `siteIcons` в `src/lib/og.ts` (его же читает `Base.astro`); вид каждого размера — `styles` в `scripts/icons.mjs`. SVG-иконки нет: браузер не грузит шрифты внутрь SVG-иконки, а контуров буквы у нас нет.

Перерисовывать — после правки шаблона или размеров в `icons.mjs`, списка `siteIcons`, токенов `--bg`, `--text`, `--accent`, версии шрифта. Команды те же: `npm run icons` (удаляет и иконки размеров, которых больше нет), `-- --force`, `-- --check`.

## Как проверяется

- **Свежесть.** В каждую PNG при рисовании записывается отпечаток (SHA-256) HTML, из которого она нарисована, и настроек снимка (флаги Chrome, масштаб, размер, прозрачность) — текстовая запись `inputs-sha256` внутри файла (`inputsHash()` в `scripts/images.mjs`). HTML собирается из данных, шаблона, токенов, градиентов, шрифтов и картинок из `public/`. `--check` собирает его заново и сравнивает: не совпало — «устарела». Chrome не нужен, поэтому это работает и в CI. Не ловится: новая версия Chrome и новая картинка по тому же адресу `https://…` — тогда `-- --force`.
- **`npm run check`** (и CI) начинается с `og.mjs --check` и `icons.mjs --check`: у главной и у каждого кейса есть карточка 1200×630, лишних (от удалённых кейсов) нет, все свежие; все иконки на месте, нужного размера и свежие, лишних (`favicon-<N>.png`, `apple-touch-icon*.png` размеров, которых нет в `siteIcons`) нет, в `favicon.ico` — 16, 32, 48. Потом — `astro check`: страница без `image` не соберётся.
- **`npm run shots`** — те же две проверки в начале, а на собранном сайте для главной и каждого кейса (`docs/wiki/site.md`): теги на месте и по одному; `og:title`/`og:description` = `title`/`description`; `og:url` = `canonical` = полный адрес этой страницы (если задан `SITE_URL` — на нём); `og:image` — полный адрес своей карточки, файл открывается и он 1200×630; каждая иконка подключена, открывается и нужного размера; `favicon.ico` открывается. Ошибки загрузки ловятся без исключений (раньше пропускался 404 на `/favicon.ico`).

## Данные сайта из Node

`og.mjs`, `icons.mjs` и `shots.mjs` читают TypeScript-файлы (`src/data/*.ts`, `src/lib/og.ts`) напрямую: Node ≥ 22.18 сам снимает типы (локально v26, в CI — 24). Импорты без расширения (`from './types'`) Node не понимает — `importTs()` в `scripts/images.mjs` подставляет `.ts`. Поэтому в `src/lib/og.ts` нет `import.meta.env` и импортов, а в данных — только то, что умеет Node (типы, константы; без `enum`).

## Где лежит

```
src/layouts/Base.astro     — meta-теги, канонический адрес, иконки, theme-color
src/lib/og.ts              — размер карточки, путь карточки страницы, список иконок
src/data/link-card.ts      — тексты карточки главной, имя сайта
scripts/og.mjs             — рисует и проверяет карточки (npm run og)
scripts/icons.mjs          — рисует и проверяет иконки (npm run icons)
scripts/images.mjs         — общее: чтение .ts из Node, токены, градиенты, шрифты, PNG, ICO, Chrome
public/og/                 — карточки: home.png, <slug>.png
public/favicon-*.png, public/apple-touch-icon.png, public/favicon.ico — иконки
```
