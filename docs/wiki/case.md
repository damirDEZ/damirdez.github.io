# Страница кейса

Сверено с кодом: 2026-11-25 (T-004, T-008; коммита ещё нет).

У каждой работы с кейсом — своя страница `/work/<slug>/`: задача → что сделали → результат → как помог ИИ. Один шаблон для сайта, ролика и игры, собран по одобренному макету `docs/design/case/case.html` (Дамир 25.11; описание — `case.md`, снимки — `case-390/1280/1920.png`). Все тексты и картинки — в `src/data/cases.ts`, компоненты `src/components/case/` их только рисуют. Пока два кейса, оба заглушки: `go-fashion` (сайт, тексты из макета) и `ai-short-film` (ИИ-фильм, тексты придуманы).

## Как устроена

1. `src/pages/work/[slug].astro` — страница на каркасе `Base`. `getStaticPaths()` делает по странице на каждый кейс из `src/data/cases.ts`. Заголовок вкладки — «<title> — Case study · Damir», `description` — лид. Карточка ссылки — `public/og/<slug>.png` (`og:type` = `article`): название, `eyebrow` и обложка кейса, рисует `npm run og` (`docs/wiki/seo.md`).
2. Сверху вниз: шапка кейса (`CaseHero`) → главы и выноска ИИ (`CaseStory`) → галерея (`CaseGallery`, если есть кадры) → «Next work» (`NextCase`, если кейсов больше одного) → контакт (`CaseContact`). Шапка и подвал сайта — из `Base`.
3. Шапка сайта на странице кейса ведёт на разделы главной (`/#work`, `/#video`…); «Hire me» — на контакт главной. У кейса свой контакт внизу (`id="contact"`).
4. `src/lib/cases.ts`:
   - проверяет данные при сборке: `slug` — только строчные a–z, 0–9 и дефис, без повторов; иначе сборка падает с понятной ошибкой;
   - `orderedCases` — кейсы в порядке, как их видит посетитель главной сверху вниз: по видимым разделам (`src/data/sections.ts`) и карточкам в них — Selected work (`href`), Video (`caseUrl`, первые `maxOnHome`), Websites (`caseUrl`). Кейсы, на которые главная не ссылается, — в конце, в порядке `cases.ts`;
   - `nextCase(slug)` — следующий по `orderedCases`, у последнего — первый; кейс один — `undefined` (карточки нет);
   - `casePath(slug)` → `work/<slug>/` (с косой чертой в конце: GitHub Pages не делает лишний переход).
5. Связь с главной — обычные ссылки из данных: `href: 'work/go-fashion'` в `selected-work.ts`, `caseUrl: 'work/…'` в `websites.ts` (появляется кнопка «View case») и `videos.ts` (карточка ролика ведёт на кейс, а не на `videoUrl`). `resolveLink()` (`src/lib/links.ts`) превращает `work/<slug>` в `/work/<slug>/` с учётом подпапки; кейса с таким `slug` нет — сборка падает («кейса «…» нет в src/data/cases.ts»). Работы без кейса ведут себя как раньше.

### Компоненты (`src/components/case/`)

| Файл | Что рисует |

| `CaseStory.astro` | главы «01 — Task…» (H2, абзацы, нумерованные шаги) и выноска «How AI helped» (H3, текст, метки) |

Общие с главной части — в `src/components/home/` (не копируются):

- `Frame.astro` — кадр; для кейса добавлены `variant="phone"` (экран телефона 9:19, скругление 20, вырез сверху), `cover` (обложка 16:8.5, ≤640px — 4:3) и градиенты `g3b`, `g3c` из макета кейса;
- `BrowserWindow.astro` — окно браузера (вынесено из `Websites.astro`; длинный адрес обрезается многоточием);
- `ContactCard.astro` — карточка контакта (вынесена из `Contact.astro`); `compact` — размеры из макета кейса: заголовок `clamp(34px, 4.6vw, 64px)`, отступы `clamp(48px, 7vw, 88px)`, кнопки `28px 0 22px` (у `ContactButtons` — свой `compact`);
- `Chips.astro` — метки.

### Раскладка

- Мета-строка: колонок столько, сколько ячеек (до 4), ≤1020px — по две (2×2); при нечётном числе последняя ячейка — на обе колонки.
- Главы: номер слева (220px), текст справа (до 680px); ≤1020px — номер над текстом. Шаги — в две колонки, ≤640px — в одну.
- Галерея — сетка 6 колонок (то же, что «3 колонки» макета): окно браузера — 4 (2 из 3), телефон — 2 (1 из 3). Ряды собираются сами: окно + телефон, следующий ряд — телефон + окно, и так далее; порядок внутри окон и внутри телефонов — как в данных. Если окон больше, чем телефонов, оставшиеся без пары широкие кадры — того же размера (2 из 3), по одному в ряд, стороны продолжают чередоваться (левый край, правый, левый…); телефоны без пары — по три в ряд. ≤640px: широкие кадры на всю ширину, телефоны по два.
- Галерея без единого телефона (как у `ai-short-film` — кадры `still`): две равные колонки, кадры 16:9 по порядку; нечётный последний кадр — на всю ширину; ≤640px — одна колонка (решение менеджера 25.11).
- «Next work»: текст слева, кадр справа; ≤1020px — кадр под текстом. У ролика на кадре Play и длительность.

## Поля данных (`src/data/cases.ts`)

| Поле | Что это | Пусто — |
|---|---|---|
| `slug` | адрес `/work/<slug>/` | обязательно |
| `kind` | `website` / `video` / `game` — от него заголовок контакта | обязательно |
| `eyebrow`, `title`, `lead` | подпись, H1 (и заголовок вкладки), строка под H1 (и `description`) | обязательно |
| `summary` | строка в карточке «Next work» на соседнем кейсе | берётся `lead` |
| `chips` | метки в карточке «Next work» на соседнем кейсе (`ai: true` — оранжевая) | меток нет |
| `liveUrl` | живой сайт `https://…` → «Visit live site ↗» (новая вкладка) | нет кнопки |
| `videoUrl` | ролик `https://…` → «Watch ↗» (новая вкладка; плеер — T-005) | нет кнопки |
| `meta` | ячейки `{ label, value }` — роль, команда, срок, год | нет `value` — нет ячейки; нет ячеек — нет строки; больше 4 — первые 4 |
| `cover` | `{ type: 'browser', media, browserLabel }` — окно браузера; `{ type: 'video', media, duration }` — кадр с Play | обязательно |
| `chapters` | главы `{ label, title, text: [абзацы], steps? }`, хотя бы одна; номер «01 —» ставится сам | нет `steps` — нет списка |
| `ai` | выноска `{ text, chips }` | нет выноски |
| `gallery` | `{ title, intro?, shots }`, кадр — `{ device: 'desktop' | 'phone' | 'still', media, caption?, browserLabel? }` | нет `gallery` или кадров — нет галереи; больше 8 — первые 8 |

- Если есть и `liveUrl`, и `videoUrl`, первая кнопка главная, вторая — вторичная.
- `media` — как на главной (`src/data/types.ts`): `image` (путь от `public/` или `https://…`), `gradient` (заглушка и цвет свечения в шапке кейса), `alt`, `placeholderLabel`.
- Общие подписи — `caseLabels`: «← All work», «Visit live site ↗», «Watch ↗», «How AI helped», «Next work», «View case →», хвост заголовка вкладки и тексты контакта по типу работы: `website` — «Want a site like this?», `video` — «Want a video like this?», `game` — «Want to work together?». Подпись «Open for projects», кнопки и почта — из `contact.ts` / `contacts.ts`, как на главной.
- Сколько показываем — `caseLimits`: `meta: 4`, `gallery: 8`.

## Как добавить новый кейс

1. Картинки — в `public/work/<slug>/` (например `public/work/my-site/home.jpg`): обложка 16:9 и шире (в шапке кейса кадр 16:8.5, на телефоне 4:3 — края обрежутся), скриншоты компьютера 16:9, телефона — 9:19 (например 1080×2280), JPG/WebP шириной 1600–2000px (телефон — 900–1100px).
2. В `src/data/cases.ts` в массив `cases` добавь объект по образцу `go-fashion` (сайт) или `ai-short-film` (ролик): `slug`, `kind`, тексты, `meta`, `cover`, `chapters`, по желанию `ai`, `gallery`, `liveUrl` / `videoUrl`. В `media` — `image: 'work/<slug>/home.jpg'`, `gradient` оставь (цвет свечения), `alt` — что на картинке, по-английски.
3. Поставь ссылку с главной, иначе кейс встанет последним в «Next work» и на него можно попасть только оттуда:
   - карточка в Selected work — `href: 'work/<slug>'` в `selected-work.ts`;
   - сайт в Websites — `caseUrl: 'work/<slug>'` в `websites.ts` (кнопка «View case»);
   - ролик в Video — `caseUrl: 'work/<slug>'` в `videos.ts`.
   Порядок «Next work» сам станет таким, как на главной.
4. `npm run og` — нарисует карточку ссылки `public/og/<slug>.png` (без неё `npm run check` упадёт); посмотри её. Название — не длиннее двух строк на карточке, `eyebrow` — одной, иначе `npm run og` скажет сократить.
5. `npm run check` и `npm run shots`. Новый кейс проверяется на 390/1280/1920 и снимается на 1280 (`shots/case-<slug>-1280.png`) — посмотри снимок.

Удалил или переименовал кейс — тоже `npm run og`: удалит старую карточку и нарисует новую.

## Как заменить заглушки Go Fashion настоящими материалами

Всё в `src/data/cases.ts`, объект `slug: 'go-fashion'` (что нужно от Дамира — `docs/design/case/case.md`, задача T-009):

1. Ссылка на сайт — раскомментируй `liveUrl: 'https://…'`: появится кнопка «Visit live site ↗». Ту же ссылку — в `websites.ts` → `liveUrl` (кнопка «Live site ↗» на главной).
2. Скриншоты — в `public/work/go-fashion/`; в `cover.media.image` — главная страница, в `gallery.shots[…].media.image` — каталог, товар, телефоны. Подписи `caption` и адреса `browserLabel` — по смыслу. Если скриншотов больше — добавь кадры (`desktop` / `phone`), ряды соберутся сами; больше 8 не покажутся.
3. Тексты — `lead`, `chapters` (задача, что делали, результат, шаги), `ai.text` и метки — словами Дамира, в тоне `docs/design/system.md` («we built…» для командной работы).
4. Мета — настоящие роль, состав команды, срок, год; неизвестное — убери `value` (ячейки не будет). Сними `needsConfirmation` с подтверждённого.
5. Сними `placeholder: true`. Тот же снимок сайта — в `websites.ts` и `selected-work.ts` (`media.image`) для главной.
6. `npm run og` (обложка и тексты попадут в карточку ссылки), `npm run check`, `npm run shots`, посмотри `shots/case-go-fashion-*.png` и `public/og/go-fashion.png`.

ИИ-фильм (`ai-short-film`) — так же: `videoUrl` (кнопка «Watch ↗»), обложка, кадры `still`, тексты, `duration`; та же ссылка и обложка — в `videos.ts` и `selected-work.ts`.

## Отличия от макета

- Нет кнопки «Visit live site ↗» — у Go Fashion ещё нет ссылки (правило «нет ссылки — нет кнопки»). Без неё на 390 страница короче на 80px (кнопка 48px + отступ 32px); на 1280/1920 высота та же. Остальное совпадает с макетом: снимки сравнены попиксельно, положение и размеры всех блоков те же (на 1280/1920 высота страницы такая же, как у макета, открытого в том же Chrome); разница — только сглаживание текста.
- Кнопка Play на кадре — как на главной (64px, ≤640px — 52px), в макете кейса — 56px (кадр общий с главной).
- Контакт — размеры из макета кейса (заголовок до 64px), а не главной (до 80px); в `docs/design/system.md` сказано «тот же блок контакта» — сделано по макету.
- Шапка сайта на 390 — как на главной (T-002): «Hire me» с полями 14px; в макете кейса — 16px.
